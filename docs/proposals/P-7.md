## Change
### 1. Documents: one row per delivered document
Fields to add/complete (additive; nothing renamed or deleted):
| Field | Type | Notes |
|---|---|---|
| Document Type | single select | add options: `CV`, `Cover letter`, `Selection criteria`, `Outreach note`, `Interview brief`, `Interview simulation` |
| Package Version | text | `prep-001/v3` |
| SHA256 | text | from the package manifest; proves the file is the approved one |
| Approved | boolean | true only after the user's `Aprobado <ID>` |
| Opportunity Ref | text | same key as Applications |
Existing fields used as they are: Document Name, File (the PDF is uploaded), Version, Notes, Application.
- Written when a version is published (Writer -> Recruiter passed): the PDF of each document is uploaded,
  linked to its Applications row, and `Latest Version` on that row is updated.
- A new version adds new rows; old rows are never deleted (published versions are immutable).

## Privacy
Baserow is local and private. Uploaded CVs contain personal data: they never go to git (unchanged), and
the future front-end must run with authentication.

## Success criteria
- Each published version produces one Documents row per document, file uploaded, SHA256 equal to the
  manifest, linked to the right Applications row; a re-run creates nothing new.
- Contacts appear linked to their offer; an ad with a no-approach clause shows Approach = no-approach.

## Rollback
