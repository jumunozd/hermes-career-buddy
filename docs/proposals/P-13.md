# P-13 Status page and pipeline board (status: PARTLY APPROVED 2026-11-21: build + D-P13-1, AP-689edb7643cf91b9f7f12c2b; D-P13-3 and D-P13-4 open)

Source: the user, 2026-11-21: a UI "para tener más comprensión de cómo es el estado y que lleve seguimiento"
(the reference is the tracking board of an earlier tool). Baserow already holds every application, but its
Kanban and Calendar views are paid (Premium), and nothing today shows **the system's own health**: which runs
happened, which sources failed, how much was found, what is waiting on the user.

## What exists today
- Baserow (source of truth for applications, documents, contacts): free Grid and Gallery views
  (`docs/BASEROW_VIEWS.md`).
- Telegram: the daily Top 3 and the Saturday report (PDF).
- Logs in `private/state/` (runs, source reads, discovery, sweeps, events, approvals, backups) that only code reads.

## Change
One local page, **`bin/hcb dashboard`**, no LLM, regenerated at the end of each search run, after the daily
backup, and on demand. Output: `private/reports/dashboard/index.html` (a single static file, inline CSS, no
external scripts or fonts: it holds personal data and never loads anything from the internet).

### Page sections
1. **Today at a glance:** what is waiting on the user (documents ready to review, offers closing in 7 days,
   follow-ups due), with the Telegram command for each («Prepara la oferta 27», «Enviada 27»...).
2. **Pipeline board (read-only Kanban):** columns by Baserow Status (Discovered → Shortlisted → Preparing →
   Ready for Review → Applied → Interview; Closed/Rejected/Withdrawn collapsed). Card: title, employer, closing
   date (red when ≤ 3 days), alignment group, link to the ad and to the Baserow row. Changes are made in Baserow
   or by Telegram, never on this page (D-P13-1).
3. **System health:** last run of each scheduled job (weekday search 07:30/12:30/16:30, Friday review, Saturday
   report, 03:00 backup) with OK / failed / missed; Telegram deliveries; last verified backup and its age;
   Baserow reachable; open approvals.
4. **Coverage:** per source (18 page_read, 24 search_discovery, e-mail alerts when P-3 is live): last read,
   result (ok / failed / no vacancies), cards found this week, consecutive failures (≥ 3 highlighted). The
   Employer Registry count by channel.
5. **Week funnel:** found → in zone → aligned → shortlisted → prepared → applied, and how the week compares with
   the previous four.

### Where it is seen
- **Mac (now):** open the file in the browser; `bin/hcb dashboard --open`.
- **Telegram:** command «Estado» answers with a 5-line summary (waiting on you, closing soon, last run, failing
  sources) and, on request, the HTML file as a document.
- **VPS (later, D-P13-3):** served only through a private channel, never on the public internet.

## Decisions for the user
- **D-P13-1 Read-only board.** Recommended: yes. Baserow stays the only place where rows change (plus the
  Telegram commands), so there is one source of truth and no second write path to secure. Alternative: Baserow
  Premium (about USD 10 per user per month) for drag-and-drop Kanban and Calendar inside Baserow.
- **D-P13-2 When it is regenerated:** after every scheduled run and the backup, plus on demand. Recommended.
- **D-P13-3 Access on the VPS:** (a) **Tailscale** (private network between your devices and the VPS; nothing
  exposed; recommended), or (b) a web server with password (HTTPS + basic auth), simpler on a phone without an
  app but exposed to the internet.
- **D-P13-4 Telegram «Estado» command.** Recommended: yes (summary text; the file only when asked).

## Not changed
Baserow schema and writes, agents, approval rules, Telegram Top 3 and Saturday report. Nothing is submitted or sent
to third parties. The page is personal data: it lives in `private/` (git-ignored) and is part of the backup.

## Implementation outline
- `hcb/dashboard.py`: reads Baserow (list, read-only), `private/state/*.jsonl`, `config/sources.yaml`,
  `config/employers.yaml`, `config/schedules.yaml`; renders one HTML template; writes atomically.
- Hook: the end of `bin/hcb daily-send`, `report-send` and `backup` calls `dashboard` (failure never blocks them).
- PM skill: «Estado» -> `bin/hcb dashboard --summary`.
- Tests: synthetic persona renders a complete page; no external URL in the HTML except the ads and Baserow links;
  a missing log or unreachable Baserow renders "unknown", never crashes; missed-run detection against the cron
  schedule.

## Validation
After one week: every scheduled run appears with the right status; a source forced to fail shows up as failing;
the board matches Baserow row for row; the «Estado» summary matches the page.

## Rollback
Remove the hook calls; delete `private/reports/dashboard/`. Nothing else depends on it.
