# P-5 Self-contained project with a public / private split (status: APPROVED by the user 2026-11-17 and IMPLEMENTED the same day)

Source: The user, 2026-11-17: Career Buddy must work from its own folder only (copy what it needs from the Job
Application Engine), and the project will be published on GitHub as a personal portfolio project (LinkedIn),
so personal, private information must be separated from the general, publishable part.

## Problem
1. Career Buddy reads the Engine folder at run time (`facts/`, `build/`, `rules/`, `voice/`), and the A-H
   evaluator and Baserow token live under `~/.hermes/career-buddy/`. The project is not self-contained.
2. Nothing is committed yet (good), but the 141 files that would go into the first commit carry personal data:
   54 files name the user; 13 hold strong identifiers (phone, email, home town, employers);
   `tests/results/*raw*` logs are full real transcripts; Writer references quote real evidence.

## Change
### 1. One folder, two zones
```
Hermes Career Buddy/
  hcb/ bin/ engine/build/ engine/rules/      PUBLIC  code + generic method (CV rules, ATS, fit, verify)
  .hermes/skills/  config/*.yaml  docs/       PUBLIC  skills, config without personal values, docs
  examples/candidate/                         PUBLIC  synthetic persona (fake facts, fake ads) so the repo runs
  tests/ (synthetic fixtures only)            PUBLIC
  private/                                    PRIVATE (gitignored, never published)
    facts/ voice/ career-goals.md target-roles.md      from the Engine (copied, then Career Buddy owns them)
    config/ (targets, sources overrides, contacts)     personal values
    applications/ state/ reports/ test-evidence/        today's runtime folders + raw test logs
    secrets/ (baserow-token)  ah-evaluator/             moved from ~/.hermes/career-buddy/
```
- `config/system.yaml` gets one key, `paths.private: private`; every personal path resolves under it.
  `HCB_PRIVATE_DIR` can point elsewhere (and the public demo points it at `examples/candidate/`).
- Engine scripts are copied into `engine/build/` and changed in one place: `ROOT/facts` becomes
  `$HCB_PRIVATE_DIR/facts` (fallback `examples/candidate/facts`). The rest stays as is.
- The original Engine folder is no longer read. It stays on disk unchanged as the user's archive (its own git
  history, `out/`, `archive/`). Facts are edited in `private/facts/` from now on.

### 2. What stays public
- the user's name as the author (README, LICENSE): it is his portfolio. No phone, email, address, visa, employer
  history, evidence, CVs, contacts, ads, Baserow ids, Telegram ids or raw logs.
- Skills, specs and prompts refer to "the candidate"; the persona is loaded from `private/facts/identity.yaml`.
- Test results: summaries rewritten without personal data (`tests/results/*.md`); raw logs move to
  `private/test-evidence/`.

### 3. Leak guard (technical, not just policy)
- `bin/hcb privacy-scan`: fails if any tracked file contains a value from `private/facts/identity.yaml`
  (name excepted), phone/email patterns, a Telegram id or a token pattern.
- A git pre-commit hook runs it, plus a unit test, so a leak blocks the commit.
- First commit only after the scan passes on the full tree.

### 4. Integrity checks that change
- Engine fingerprint (git status of the Engine) becomes a hash of `private/facts/` + `engine/` recorded per
  version, so "facts unchanged during a run" still holds.
- A-H manifest pins: the facts files are copied byte-identical, so hashes hold; only the paths change.
  The manifest is re-pinned under a new approval record (same procedure as AP-58f12c43e543f77ba6e6b28e).

## Not changed
Rules (never apply, never invent facts, approval for changes), Baserow as source of truth, the Hermes
profile `career-buddy`, Telegram, schedules.

## Validation

## Decisions for the user
- D-P5-1 Private zone inside the project (`private/`, gitignored), recommended; or outside (`~/.hermes/career-buddy/`).
- D-P5-2 Name in public files: author only (recommended) / nowhere.
- D-P5-3 Engine history (`out/` past CVs, `archive/`): stay in the Engine folder (recommended) / copy into `private/`.

## Also before shipping (found by Hermes's own review, 2026-11-17; all three confirmed and FIXED the same day)
- `hcb/daily.py` marks offers as notified when the digest is saved, before delivery is confirmed: a failed
  Telegram send would lose them. Fix: notified only after confirmed delivery.
- `daily.build_digest` and `rules.alignment_key` order offers differently. Fix: one ordering function.
- `config/schedules.yaml` calls `bin/hcb report build`, which does not exist.
