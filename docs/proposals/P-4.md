# P-4 From discovery to ranking: quick vacancy confirmation + cleaner digest (status: APPROVED as option B, 2026-11-16, AP-8b0ed42a08712e3b6d21afc1)

Source: RT-13 (2026-11-16) and the user's request "prepara la propuesta".

## Decision (The user, 2026-11-16): option B, not the one-tap confirmation
"Encajo con las ofertas cuando se alinean con mis roles objetivos." So:
- The digest and the Saturday Top 5 are ranked by the deterministic **alignment** with the target roles
  (catalogue group A..E, exact title first, Strategic Entry first, more target roles bridged first, closing date).
  No A-H during search. Out-of-catalogue roles are never shown.
- **A-H VERIFIED runs only when the user says `Prepara la oferta X`**, which records his confirmation that the
  vacancy is open (approval `vacancy_open`, performed_by user). The fit is shown to him before the Writer;
  a knockout stops and asks, as with Shaw.
- Contact research (P-2) now triggers on aligned `principal` offers without waiting for A-H.
- Section "Change" 1 below (`Abierta` command) is NOT implemented. Sections 2-4 are superseded by the above.
- Rollback: `config/system.yaml ranking.basis: fit`.

## Problem
RT-13 found 42 ads and 6 candidates, but none reached the main ranking:
- A-H in PRELIMINARY withholds every score. The original evaluator gives a numeric fit only in VERIFIED,
  and VERIFIED requires `performed_by: "user"` with `vacancy_open_confirmed: true`. It rejects
  `performed_by: "agent"` by design (evaluator.py line 70 and its tests; folder is read-only for this project).
- Without a fit there is no `principal` category, so contact research (P-2) never runs.
- 3 PRELIMINARY A-H runs (~31K input tokens each) gave no score; one was on an out-of-zone ad.
- The digest showed out-of-catalogue roles (Trades Assistant, Materials Tester) as "pendiente de revisión".

## Why not "the agent's read counts as verification"
That was the first idea. It would mean writing `performed_by: "user"` for something the agent did, which is
false, or changing the user's A-H evaluator, which lives outside this project and is read-only here. Neither is
acceptable. The confirmation must stay the user's. It can be made almost free for him.

## Change
### 1. One-tap confirmation from the digest (new command)
Each digest item shows the employer's own link and the time the system read it:
`🔗 tasnetworks.com.au/... (leído hoy 07:41)`.
The user replies **`Abierta o-3f2a1c`** (or `Abiertas o-3f2a1c, 41`). The PM:
1. records an Approval Record of type `vacancy_open`: performed_by user, checked_at now, the URL and the
   evidence "The user confirmed from the digest; employer listing read by the system at <time>";
2. runs A-H **VERIFIED** with that record (the evaluator accepts it as is);
3. classifies with the real fit (> 50 % -> `principal`), then contact research if eligible;
4. replies with the fit and category, e.g. `o-3f2a1c -> fit 68 · Ranking`.
`Cerrada o-3f2a1c` marks it closed. Nothing else changes; `Prepara la oferta ...` still needs its own command.

### 2. A-H only where it can matter (token saving)
- **PRELIMINARY at discovery**: only for in-zone ads whose title matches the catalogue (groups A-D) or whose
  duties give `needs_review` (3+ bridge signals incl. improvement). Max 3 per run. Purpose: knockouts and
  mandatory gaps early (like Shaw's K7), not a score.
- **VERIFIED**: only after `Abierta`, one run per offer.
- Everything else: Seen log only.

### 3. Contacts ready when the user confirms
`bin/hcb contact trigger` also accepts `pendiente_revision` offers with catalogue group A-D and
`category_hint: principal_candidate` and no A-H knockout, still max 3 per run. Contacts are then ready
when the user confirms, which matters for the same-day call. Private employers only, as in P-2.

### 4. Cleaner digest
The digest shows: `principal`, `exploratoria`, and `pendiente_revision` ONLY when there is a catalogue match
(A-E) or `needs_review`. Out-of-catalogue roles are never shown; the Saturday report gives only their count
("otros 4 anuncios fuera de catálogo").

## Risk
- The user confirms without opening the link: the evidence records that the system read the employer page and
  when, so the confirmation is informed, and the user's word is what A-H records, as today.
- Fewer PRELIMINARY runs may catch a knockout later: VERIFIED still runs before any preparation.
- Contact research on not-yet-confirmed offers spends tokens on offers the user may skip: capped at 3 per run.

## Success criteria
- RT-14 replay of the RT-13 inventory: out-of-catalogue roles not in the digest; at most 3 PRELIMINARY runs, all in zone.
- `Abierta <code>` produces a VERIFIED A-H with numeric fit and the right category, recorded with an approval id.
- Tokens per search run go down against RT-13.

## Rollback
Config switches `digest_filter_catalogue`, `ah_preliminary_scope`, `contact_trigger_pending`; the command
`Abierta` can be removed from the parser. Versioned skills and code.
