# P-15 Search discovery v2: agency roles, aggregators, freshness, dedup, native search alarm (status: PROPOSED 2026-11-28, nothing built)

Source: the user, 2026-11-28. A Business Analyst Specialist role (Chandler Macleod for Rio Tinto, Bell Bay Smelter, 12-month
contract, posted 27 Nov 2026, closes 27 Dec 2026) was found by the user with ChatGPT, not by Hermes; Hermes only registered
it when the user asked (Baserow row 39, `user_explicit_selection`). Feasibility tests the same day, read-only, no code change:
1. Exa (today's backend, `agent-reach web search`, free tier): 13 queries, ~1-2 s each.
2. OpenAI native web search through Hermes (`web.search_backend: openai-native`, temporary, AP-37213becbc13f04bffe1efdd,
   restored to exa afterwards): 8 queries in one turn, 148 s.

## What the tests showed
| | Exa | OpenAI native |
|---|---|---|
| Finds the Rio Tinto case | yes: Regional Jobs (movetomore.com.au) and ViewJobs, same ad id `00d57e33...` | yes: resourcejobs.au + SEEK category pages whose snippet quotes the ad, "Listed nine hours ago" |
| Direct SEEK / Jora ad URL (`/job/<id>`) | never | never (0 of 80 results) |
| Dates | `published_at` and "Date posted / Closes" in the indexed text | "Listed X ago" on SEEK category pages; ads mostly undated |
| Role queries ("Business Analyst job Tasmania") | 4-6 ads out of 10, mostly stale; 1 of ~19 under 14 days | mostly SEEK / Jora / Indeed category pages, some US noise (Hobart NY); a few direct ads Exa missed (TSS BA 528344, Meander Valley BA, TasNetworks CI Specialist on WORK180) |
| Where it runs | code (`bin/hcb sweep`), deterministic | only inside a model turn; the model transcribes results |
| Cost | Exa free tier | the user's ChatGPT plan usage, no separate bill |

Why Hermes missed it:
- Discovery searches by employer name only. Bell Bay's careers page lists Rio Tinto's own Workday roles, not the contract
  roles Chandler Macleod (Rio Tinto's exclusive contract provider in Australia) posts.
- ViewJobs `/listing/` URLs are not recognised as job ads (`discovery.classify_url` → None, the result is dropped).
- Dedup: `seen.job_key` compares the location as text. "Bell Bay" vs the stored "Bell Bay Tasmania" → `new`: the
  ad would have been registered twice. The shared aggregator id was not used.
- Jora's robots.txt disallows `/job/` for named crawlers (ExaBot included); SEEK job pages are never opened by rule.

## Changes
1. **Employer + agency queries (code, Exa).** For tier-1 employers, `employers.yaml` gains `agencies:` (Bell Bay / Rio
   Tinto: Chandler Macleod). `discovery.query_for` adds rotating queries `"<agency>" "<employer>" <site> job`, inside the
   existing budget (`max_queries_per_run: 4` → 6, 12:30 and 16:30 runs). Agencies are a source of ads only: the contact
   policy for agencies is unchanged.
2. **More aggregator patterns, never opened.** `JOB_URL` / `AGGREGATOR_PATH` learn ViewJobs `/listing/<id>`, Regional
   Jobs `/job/<id>`, resourcejobs.au `/jobs/`, Jobstralia `/detail/`, jobau.org, Jooble `/jdp/`, ZammeJobs, WorkinAUS,
   chandlermacleod.com `/job-details/`. Aggregators stay hints (the card is the result text; the user sends the full ad).
   SEEK, LinkedIn, Indeed and Jora job pages are never opened.
3. **Freshness.** A card takes its date from `published_at`, else from "Date posted / Listed X ago / Posted Xh ago" in
   the result text; older than 45 days is dropped (today's `MAX_AGE_DAYS`); no date → kept, marked `date: unknown`.
4. **Dedup that survives several sources.** `seen.job_key` normalises the location (drops TAS, Tasmania, Australia,
   On-site, Remote, Hybrid, postcodes) so "Bell Bay", "Bell Bay, TAS" and "Bell Bay Tasmania" are one key. A long id
   shared by two aggregator URLs (UUID, 16+ hex) is a job identity: same id → same ad. Same employer + title with a
   different place stays `possible_duplicate` for the user, as today.
5. **Native search alarm (model turn, optional, D-P15-2).** In the 12:30 run the Job Hunter runs 2 fixed native web
   searches (titles from the top of the catalogue + "Tasmania", rotating). Only results that name a role title and a
   Tasmanian place become cards `pendiente: falta el aviso completo`, with the aggregator / employer link when one was
   returned, else the SEEK category page as the link for the user to open. The Job Hunter passes results to
   `bin/hcb discovery ingest` as JSON (title, url, snippet, date_shown) and code classifies and dedups them: the model
   never decides a category. Requires `web.search_backend: openai-native` permanently (then the Writer's and the
   Research agent's searches also go through OpenAI) and the guard change below.
6. **Guard: no portal page reading (P-14 hook).** `web_extract` / browser tools are blocked for SEEK, LinkedIn, Indeed
   and Jora job pages, so the rule no longer depends on instructions. Needed with or without change 5.

## Not proposed
- Broad role-only searches as a main source (too noisy, mostly stale or category pages).
- A paid search API (Bing / Brave / Google): the native search already sees SEEK; revisit only if change 5 is not approved.
- Reading SEEK / Jora pages in any form.

## Decisions for the user
- **D-P15-1** Changes 1-4 and 6 (code and config, Exa stays the backend, no new service). Recommended.
- **D-P15-2** Change 5 (permanent `openai-native` backend + 2 native searches per weekday). Recommended after a 1-week
  trial with a usage check; it can be switched off by restoring `search_backend: exa`.
- **D-P15-3** Agencies per employer: start with Chandler Macleod for Rio Tinto / Bell Bay; the user adds others.

## Success criteria
- The Rio Tinto Business Analyst Specialist ad (and ads like it) would reach the digest within one weekday run of being
  posted, once.
- No duplicate Baserow rows from aggregators of the same ad (replay of the 26-28 Nov results).
- No SEEK / LinkedIn / Indeed / Jora job page opened (guard log).
- Discovery stays inside the 180 s terminal limit per run.

## Rollback
Each change is its own commit; `search_backend: exa` restores today's search; the new aggregator patterns and agency
queries are config entries that can be removed.
