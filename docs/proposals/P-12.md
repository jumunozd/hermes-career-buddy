## Change
1. **Employer Registry** (`config/employers.yaml`, public: company names and careers URLs only): every employer
   above with sector, tier (1 = group A-C roles likely in zone), Tasmanian sites and channel (`page_read`,
   `email_alert`, `search_discovery`, `out_of_zone`). The Research Agent keeps it current in the Friday review
   (new employers from tenders, major projects and awards) and proposes additions; the user approves them.
2. **Group P** added to `config/sources.yaml` one by one after a confirmation read (job link pattern, location
   field, cadence `first_run:mon` or `tue,thu`), paced as today. Expected: 9 -> about 20 read sources.
3. **E-mail alerts as the main coverage channel** (P-3, the user: SEEK, LinkedIn, TasNetworks):
   - SEEK and LinkedIn: saved searches per role family A-C, location Tasmania, daily or instant.
   - TasNetworks, TasPorts, TasWater, Hydro/Entura, Marinus Link, the councils on applynow / TechnologyOne, and
     every group W employer: the platform's own job alert, location Tasmania.
   - A checklist for the user (portal, search, frequency) is generated from `employers.yaml`.
4. **`search_discovery` as the safety net** for group W and X employers until their alerts arrive (feature
   `web_discovery` is already approved; each source is still `enabled: false`).

## Decisions for the user
- **D-P12-1 Alerts mailbox.** P-3 chose a dedicated Gmail with a read-only token (`gmail.readonly`).
  Option: use the dedicated iCloud mailbox you already created (one mailbox for incoming alerts and outgoing
  packages). Trade-off: iCloud has no read-only permission; its app password can read, send and delete, so
  safety rests on the code (reads only the alerts folder and allowlisted senders, never deletes). Recommended:
  **keep P-3 (Gmail read-only)** for alerts and iCloud for sending.
- **D-P12-2** Add group P (14 employers) after the confirmation reads.
- **D-P12-3** Create `config/employers.yaml` and let the Research Agent propose additions every Friday.
- **D-P12-4** Turn on `search_discovery` for groups W and X until their alerts work.

## Not changed

respected (no login, no identity spoofing, no SEEK `/job/` pages, no LinkedIn automation).
