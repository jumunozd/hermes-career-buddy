# P-10 Telegram message interface and application delivery (status: APPROVED 2026-11-20)

Source: the user's change request "Telegram Message Interface & Application Document Delivery" and a hand
sketch (2026-11-20): a daily message with the Top 3 (name, link, `Prepare Docs` button, who to call) and the
other opportunities ordered by fit. Presentation and interaction change only: agents, approval rules,
Baserow and the preparation workflow stay as they are.

## What Hermes already supports (checked in the installed version)
- Telegram inline keyboards and callback dispatch (python-telegram-bot), already used for approvals/pickers.
- Button taps gated by the same allowlist as messages (only the user's account).
- Plugin API `register_telegram_handler(factory)` to add a CallbackQueryHandler scoped by pattern.
- An email platform adapter (IMAP/SMTP), not configured.
- Missing: `hermes send` cannot attach buttons; a plugin has to send the keyboard.

## Change
1. **Daily message (code, `bin/hcb daily` + `daily-send`).** TOP 3 BEST FIT: rank, title and company,
   **alignment** (group A-E and catalogue title; decision D-P10-1), link to the ad, `Prepare Docs` button,
   and who to call (name + phone from the ad, or "no information"). OTHER OPPORTUNITIES: the rest, best to
   worst; exploratory ones kept separate. Silent when nothing is new (unchanged).
2. **Plugin `career-buddy-buttons` (profile career-buddy).** Callback `hcb:prep:<Baserow row id>`:
   authorised user only -> idempotency check (a second tap does nothing) -> Baserow Status `Preparing` ->
   answer "Document preparation started" -> hands the PM the existing instruction
   `Prepara la oferta <ID>` (same approval semantics, no new rules). Also sends the daily message with
   its keyboard.
3. **Package delivery by e-mail** when Writer -> Recruiter pass: subject `Application Ready — [Job Title] |
   [Company]`; title, employer, ad link, alignment (and A-H fit, computed at preparation), short Recruiter
   verdict, documents attached, and a short message in the user's voice (existing `Prepara contacto` flow).
   Recipient allowlist: only the user's address. Packages stay in `private/applications/` and Baserow
   Documents.
4. Tests: button tap on a test row (twice: no duplicate), one real e-mail to the user.

## Decisions
- **D-P10-1 Fit shown in the daily message: alignment, no A-H during search** (the user, 2026-11-20).
  P-4 B unchanged; A-H still runs when preparing, and its fit goes in the delivery e-mail.
- D-P10-2 **Sender: the user's dedicated communication mailbox (iCloud Mail), created for job hunting** (address kept in `private/config/`). Mechanism: plain SMTP over TLS from `bin/hcb` (iCloud requires an app-specific password, created by the user and stored outside the repo); recipient allowlist. Chosen over the Hermes email platform adapter, which would also open an inbound e-mail channel to the agent.
- D-P10-3 **Saturday report by e-mail** once sending works (the user: "que mande los documentos al correo"); Telegram keeps a one-line notice.
- D-P10-4 **Plugin approved** (configuration change in the career-buddy profile).

## Unchanged
The user always submits applications; Hermes never submits or contacts anyone; Writer and Recruiter
methods; Baserow is the source of truth; Telegram is the instruction channel.

## Rollback
Disable the plugin (`hermes plugins disable career-buddy-buttons`), daily message falls back to the current
text digest; e-mail delivery off with a feature flag.
