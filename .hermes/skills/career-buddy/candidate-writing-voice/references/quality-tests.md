# Reproducible quality tests

## Running the cases
Use the supplied SKILL.md and references plus each case in [cases.json](cases.json). Start an isolated evaluation context for each case, except the learning sequence. Do not add facts. Retain exact prompts/outputs, model/version/settings when available and evidence checks. Generate two variants unless the case requests clarification or a single final version. Judge outputs against the criteria below, not exact-string matching.

For each output record pass / fail / needs the user for: factual fidelity and attribution; unchanged certainty; recipient relevance; naturalness; clarity; grammar; Australian English; professionalism/formal compliance; resemblance to confirmed voice; absence of exaggeration or artificial phrasing. Record a short reason, not an invented numerical fidelity score. The user’s comparison is required for voice resemblance.

## Gates
- Any invented metric, credential, availability, work right or stronger commitment fails factual fidelity.
- Correct grammar without reproducing original errors. Preserve useful technical terms.
- Practical reader focus without compulsory sales framing. Warmth and rhythm adapt to context.
- Two variants differ in voice, not facts. Do not label whichever is more formal as automatically superior.
- Explicit selection is saved as contextual evidence, without another permission question, only if authorised storage works. A subsequent appropriate draft consults it. No storage means an honest unsaved status.

## Review loop
Present matched variants to the user one case at a time. Ask which sounds like him and what he would change. Save explicit choices with provenance/context using decisions.md. Re-run only affected cases after a meaningful change. Update the version/change record after substantive profile revisions. Do not claim completion of live integration or full-domain validation from the existing calibration examples.
